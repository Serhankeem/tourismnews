# PR #31 — ECOS 일반여행수입·지급 자동 갱신과 홈페이지 연결 준비

## 현재 상태
- 공식 ECOS `301Y013`의 일반여행수입 `2C1Y00`, 일반여행지급 `2C2Y00`는 실제 Preflight에서 식별됨.
- 2025-10~2026-09 사이 301Y013/301Y014 24개 수치 비교 완료. 사용자 제출 관광수지 CSV의 표시 정밀도(백만달러 한 자리) 24/24 일치.
- 다만 KTO CSV 공식 다운로드 경로·공표 빈티지/잠정·확정·저작권 조건 검토가 아직 완료되지 않음.
- **`macro_sources.json` 운영 연결은 disabled, mapping/rights/crosscheck 미승인 상태 그대로 보존**.
- 기존 사이트는 수입·지출이 실제 API 승인 데이터로 연결되는 경우 표시할 수 있는 KPI·그래프를 이미 갖추고 있음. 새로 중복 구현하지 않음.

## 구현 변경
1. `src/macro/ecos.py` — 조회 범위(`queried_ranges`)를 각 계열별 반환해, 이번 요청이 실제로 검사한 월을 원장에서 식별.
2. `src/macro/engine.py` — 초기 정상 수집 시 설정 시작월부터 백필하고, 이후 매일 최근 24개월과 이전 수집 이후의 누락 가능 범위를 다시 조회. 기존 오래된 관측치는 유지하고, **조회하지 않은 과거월을 최신 응답의 결측으로 잘못 처리하지 않음**. 실측 정정은 기존 revision 원장에 이력 저장. mapping/rights/crosscheck `verified` 전에는 승인되지 않은 ECOS 수집과 공개를 차단.
3. `site/macro.js` — 수입과 지급 **두 자료가 모두 검증되어 연결되었을 때만** 관광수지 계산값(수입−지출)을 홈·마크로 모니터 KPI에 표시. 통화는 백만 US$, 기준월 및 계산값 주석 표시. 계산값은 독립적인 공식 공표치로 오인되지 않도록 별도 설명. 둘 중 하나라도 미연동·다른 기준월·유효성 실패 시 생략.
4. 회귀 테스트로 초기 백필, 이후 24개월 재조회, 정정 감지, 오래된 값 보존, 비활성 데이터 은닉, 승인 가드 확인.

## 반드시 유지할 조건
- 이 PR의 GitHub main 병합은 기존 수집/배포 워크플로를 트리거할 수 있으나, 수치 수집 source 및 두 indicator는 여전히 disabled.
- API Secret은 기존 서버사이드 Actions에만 전달; 브라우저에 Secret이나 ECOS API 호출 추가 없음.
- `data/live`, `collector_state`, `site/data`, news, research 운영 JSON, pipeline 계약은 직접 변경하지 않음.
- 기존 임시 후보 비교 및 Preflight 정책의 안전장치 제거 금지.
- KTO 공식 출처·이용조건 검토와 운영 승인은 **다음 별도 PR**에서 증빙을 첨부해 처리해야 하며 자동 승인 불가.
- 승인 전 홈페이지에 실제 수치가 나타나지 않는 것이 **정상**.
- 부호 있는 관광수지는 수입−지출 **파생값**, 실측 원장 지표 2개와 구별.
- 매일 현재 Macro Monitor schedule(12:20 KST 기준)에 연동될 수 있도록 기존 파이프라인 구조 재활용. 예약실행은 GitHub 정책에 따라 지연 가능.
