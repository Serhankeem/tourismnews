## 결과

- 기존 28개를 그대로 유지하고 검증된 후보 **32개**를 기존 `rss` 어댑터에 추가했습니다(총 60개). 아주경제·파이낸셜뉴스·헤럴드경제를 우선 배치했으며 종합·경제·지역·방송을 함께 연결했습니다.
- robots-aware `Loader`를 통해 **32/32개 접속·XML/항목 파싱 성공**, **3,648개 항목**을 받았습니다. 새로운 DB·워크플로·관리자 UI는 없습니다.
- 2026-11-12T15:00:21+09:00 기준 직전 168시간의 `Direct` 기사: **34개 URL**, 최신 운영 원장·발견 이력과 중복 제거 후 **34개 신규**. 18개 발행처에서 직접 관련 항목을 확인했습니다. 동일 URL/HTTP·HTTPS/www/추적 변수/쿼리 순서 변형은 같은 기사로 취급하고, 다른 발행처의 독립 URL을 제목 유사성만으로 합치지 않습니다. 기존 동일 발행처의 제목·숫자·72시간 유사 기사 중복 제거도 유지합니다.
- **신규 게시 가능 기사 0개**: 32곳 모두 `publication.status=review`, `scope=none`, `reuse_excerpt=false`, `analysis_fields=["title"]`입니다. 수집 성공을 공개 허가로 승격시키지 않습니다. 미승인 제목은 운영용 발견 원장에 원문 대신 해시만 기록합니다.
- 아주경제는 현재 피드가 약 3.4 MB여서 기존 2 MiB 상한에 걸렸습니다. 기존 로더의 상한을 **4 MiB**로 제한적으로 늘려 재검증했고 1,000개 항목을 처리했습니다. 상한·robots·HTTPS·리디렉션 대상 재검사·지연·재시도 제한을 유지합니다.
- 머니투데이·오마이뉴스의 기존 HTTP 주소는 같은 호스트/경로의 HTTPS 주소로 연결했고 실제 로더 성공으로 확인했습니다. 원래 URL은 각 공급원의 `validation.original_feed_url`에 남겼습니다.

## 날짜 보완 — 이전 61개 원응답 재사용

기존 Issue 댓글은 58개 정상 RSS와 4,830개 항목, 최근 7일 4,603개를 기록했습니다. 저장된 61개 검증 결과/헤더/추출 항목을 재사용하여 **각 응답의 HTTP Date**를 기준 시각으로 재계산했습니다. 결과는 최근 7일 **4,603개로 동일**하며, 그 수치에는 미래 날짜 19개가 이미 제외돼 있었습니다. 이전 보고서에 미래 최댓값이 함께 노출된 것을 최신 기사 검증 성공으로 해석하면 안 됩니다.

1. 매일경제의 RFC 형태 `+09:00`은 Python `email.utils`가 오프셋을 잃을 수 있습니다. RFC 오프셋을 `+0900`으로 정규화합니다. ISO 오프셋은 그대로 보존합니다. 날짜에 시간대가 없으면 기존 수집기와 같이 KST를 적용합니다. 숫자 월을 사용하는 노컷뉴스 날짜도 명시적으로 파싱합니다.
2. 국민일보 15개·한라일보 4개는 **원래 RSS에 명시된 GMT 시간이 HTTP Date보다 미래**입니다. 예: HTTP Date `2026-11-12 05:46:52 GMT`보다 한라일보 `13:10:56 GMT`가 늦습니다. 한국 현지 시계를 GMT로 잘못 표기했을 가능성이 있으나, 공급자 확인 없이 9시간을 빼면 공표일을 임의 변경하게 됩니다. 선언된 GMT를 보존하고 미래 항목을 보류합니다. 새 32개 응답 코호트에서는 미래 항목 **18개**이며 아래에 발행처별로 표시합니다.
3. 미래 허용 오차 5분을 없애 검사 시각을 1초라도 넘는 새 기사는 수집/공개 및 7일 코호트에 넣지 않습니다. 원래 원장 기록은 수정하지 않습니다. 항목 날짜가 없거나 잘못되면 현재 시각으로 대체하지 않습니다. Atom updated는 발행일로 사용하지 않습니다.

`issue47-date-correction.json`에 58개 파싱 성공 피드의 응답 시각·보정 집계를, `issue47-live-duplicates.json`에 61개 원장 결과와 최신 운영 데이터 중복 대조를 기록했습니다. 원래 4,830개 관측은 정규화한 URL로 4,796개이며 공개 97개·보관 원장 110개·발견 원장 4,928개와 URL 중복은 각각 0개였습니다. 이전 수동 관련성 92건도 최신 원장/발견 이력과 URL 중복 0건입니다.

**이전 수동 92건과 이번 자동 34건은 서로 다른 집계입니다.** 이전에는 61개 피드의 수동 제목 검토였고 이번에는 그중 선정한 32개 새 응답을 기존 자동 규칙으로 선별했습니다. 일반 여행 소개·할인·행사·인물·사건사고 등의 폭넓은 수동 후보를 강제로 자동 게시하지 않습니다. 관련 기사 비율을 올리려고 간접 관련 편집 승인 경로를 완화하지 않았습니다.

## 격리 검증과 운영 데이터 보존

`data/live`의 `6669293e39e25a3c54902e778e00e54a18989c84` 커밋을 읽기 전용으로 추출하여 `/workspace/work/step5b/live-baseline`에 보관하고 별도의 `isolated` 복사본으로 실행했습니다. 기준 데이터는 News/Newsroom 97개, 내부 원장 110개, 발견 원장 4,928개, 보고서 137개입니다. 오래된 main의 로컬 뉴스 58개를 기준으로 사용하지 않았습니다.

- 실접속 시각: 2026-11-12 14:54~14:55 KST. 각 배치 결과를 즉시 저장했습니다. 검증 실행은 그 실제 응답을 기존 어댑터/engine에 재생하여 네트워크 중복 호출 없이 두 번 수행했습니다. 두 번째 실행의 신규 발견 수는 0입니다.
- 검증 실행에 모든 60개 공급원 설정을 전달해 기존 발행처 권리를 유지했습니다. 새 공급원 32개만 검사하고 기존 공급원 네트워크 호출은 `outside_isolated_new_source_test_scope`로 명시적으로 제외했습니다. 기존 수집기·권리 게이트의 실패 시 보존 경로를 통과하므로 출판 단계의 `failed`는 전체 32개 수집 실패를 뜻하지 않습니다. 새 출판 승인 공급원도 없고 기존 출판 공급원도 이번 검사에서 재요청하지 않았기 때문입니다. 발견 단계는 32곳 모두 성공했습니다.
- 공개 News/Newsroom·리서치·보고서·Macro·브리핑과 뉴스/리서치/Macro 내부 원장의 **바이트 동일성**을 확인했습니다. 격리 복사본의 health·발견 이력·수집 메트릭만 갱신됐습니다. `baseline.json`은 파일별 SHA-256이고 `validation.json`의 `preservation`은 격리 실행 전후 비교입니다.
- 실제 저장소 `site/data`, `collector_state`, `macro_sources.json`, `reports_sources.json`, TOURGO 승인 범위, `pipeline.json`, `.github/workflows`에는 변경이 없습니다. 월 통계·TOURGO API를 호출하지 않았습니다. 운영 Actions 실행·data/live 쓰기·병합·배포도 하지 않았습니다.
- 기존 6개 공개 필드(`title`, `source`, `published_at`, `url`, `category`, `keywords`)를 유지합니다. 원문 본문·설명·이미지·새 공급원 제목 원문을 PR에 싣지 않습니다. 응답 해시와 추출 항목의 제목/URL 해시로 검증 근거를 남깁니다.
