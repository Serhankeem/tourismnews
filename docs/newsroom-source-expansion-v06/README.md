## 1. 야놀자리서치 참고 모델

[공식 언론보도 목록](https://www.yanolja-research.com/media/list?lang=kr&sub_type=1)은 HTTP 200이었다. 단일 응답에서 보도자료/언론보도 구분, 언론사(`h6`), 제목(`h4.title`), 날짜(`span`), 새 창 링크를 확인했다. 목록의 링크는 원 발행처 URL이 아닌 `/media/link/{id}` 중계 주소였다. 표시된 전체 709건은 야놀자리서치 연구·활동 관련 보도 목록이며 일반 관광산업 기사 수가 아니다.

참고할 점은 **발행처·제목·발행일·원문 접근 경로의 분리**다. 페이지 이동, 중계 링크 추적, 개별 기사 본문 및 이미지 수집은 하지 않았고, 이 목록을 뉴스 DB나 발견 API로 연결하지 않았다. 원 발행처의 공식 피드와 직접 URL이 필요하다. 화면 디자인은 수정하지 않았다.

## 3. 권리 판단

무료·광고 없는 비상업 운영이라는 기존 정책을 전제로 조사했다. **개인용 RSS 구독, 일반 링크 가능성, 본문 재사용 허락, 자동 수집/DB 색인 계약은 서로 다른 문제**다. 제목이 언제나 저작권 보호 대상이라거나 반대로 언제나 자유 이용이라고 단정하지 않는다. RSS 제공 자체·HTTP 200·robots 허용·공공기관이라는 이유만으로 이용허락을 승인하지 않았다.

뉴스1 약관은 “로봇, 매크로, 스파이더, 스크래퍼 등 자동화 도구”의 수집·이용 및 서면 동의 없는 크롤링/스크래핑을 제한한다. 서울경제는 개인 비상업 RSS 이용만 명시한다. 세계일보는 개인 구독 뉴스의 허락 없는 공중 배포·재RSS를 금지한다. 투어코리아·호텔앤레스토랑은 저작권 정책에서 사전 허가를 요구하므로 제목·링크만 선별 색인하는 이번 사용 범위에 대한 별도 확인이 필요하다. 계약 여부·비용·수신 범위·갱신 의무가 확인되지 않은 곳은 **미확인**이며, 무료 계약 가능성도 추정하지 않는다.

공식 페이지와 robots는 네트워크 정책상 허용된 HTTP 경로를 통해 요청했다. robots_disallowed는 사이트의 경로 제한이다. robots_unverified:http_503은 robots 응답 확인 실패로서 실제 뉴스 피드 중단 또는 영구 차단의 증거가 아니다. 프록시 경유 HTTP 오류의 발생 주체를 사이트/WAF/중간망 중 하나로 단정할 수 없다. 미확인 상태에서는 Loader가 안전하게 중단하며 HTTPS·robots 차단을 우회하지 않는다.

## 4. 실제 연결 및 최소 코드 보완

**추가 활성 공급원: 0.** 연구 문서의 후보 25곳을 `sources.json` 등록 수에 더하지 않는다. 기존 26개 소스·권리 상태를 보존했다. 본문을 수집/AI 가공하는 기능을 추가하지 않았다.

1. `sources.json`: 기존 국내 발행처에 검증한 원문 도메인과 고유 발행처 식별자를 명시했다. 서울시의 4개 RSS 경로는 동일 발행처 1곳으로 묶는다. 연합뉴스는 경제 전문매체와 구분해 `general_news`로 표기하되 review를 유지한다.
2. `src/engine.py`: 도메인이 명시된 기존 국내 피드에서 다른 호스트의 링크가 나오면 `attribution_holds`로 신규 입고를 보류한다. 비슷한 도메인 접미사·중계 URL·사용자정보 포함 URL을 원 발행처로 오인하지 않는다. 기존 저장 기사에 이 규칙을 소급해 삭제하지 않는다.
3. `src/diversity.py`, `src/coverage.py`: 실제 공개 대상만으로 발행처 단위 수·상위 3곳 집중도·7일 국내/Korea-direct 수·도메인 분포를 집계한다. 국내 발행처라는 사실로 `korea_direct`를 부여하지 않는다. 기존 지표는 보존하고 세부 집계를 추가했다.
4. 출처별 `news_conversion_last7d`: 같은 실행에서 받은 최근 7일 **고유 URL ID 코호트**의 관측 → 산업 후보 → 권리 및 Indirect 승인 충족 → 현재 실제 공개 → 이번 신규 공개를 구분한다. 누적 게시 수를 한 번 받은 피드 건수로 나누지 않는다. 실패는 `null`(미관측), 정상 0건은 0, 분모 0의 비율은 `null`이다. 공시·통계는 뉴스 전환율에서 제외한다.
5. 전재 판별은 제목만으로 확정할 수 없다. `[보도자료]` 등 명시적 제목 표시는 배포 표방 신호, 서로 다른 발행처의 72시간 이내 거의 같은 제목·동일 숫자는 `possible_shared_headline` 신호만 기록한다. 별도 취재로 단정하거나 기사를 삭제하지 않는다. 서로 다른 제목도 독립 취재의 증거가 아니다. 이 제한을 집계의 정의에 남긴다.

기존 PublicationGate/HNR review 3건, 관련성·editorial tier·Indirect 승인 규칙, 확정 브리핑, 공개 6필드는 그대로다. 제목·출처·발행일·URL·카테고리·키워드 이외의 기사 공개 필드를 추가하지 않았다.

## 8. 사용자 조치와 남은 과제

**아직 국내 일일 뉴스 공급 분산은 해결되지 않았다.** 기존 3개 전문매체 집중도는 88.89%이며 경제·종합·민간기업의 새 공개 기여는 0이다.

1. 우선 투어코리아·호텔앤레스토랑·매일경제·뉴시스의 공식 제휴/저작권 담당자에게 **무료·광고 없는 공개 링크 큐레이션**의 자동 색인 조건을 확인해야 한다. 6필드, 원문 직접 링크·출처 표시, 본문/사진/요약/AI 학습 없음, 수집 빈도·보관/삭제·캐시 의무를 제시하고 서면 범위를 받아야 한다. 뉴스1 등 명시적 자동화 제한 매체는 서면 승인 전 수집하지 않는다. 이번 작업에서 문의를 발송하거나 계약을 체결하지 않았다.
2. 공공기관 보도자료의 공식 RSS/API와 개별 자료 공공누리/제3자 권리 조건을 확인한다. 기관명만으로 공공누리 1유형을 적용하지 않는다. 민간 관광기업에도 공식 배포 피드와 메타데이터 색인 허가가 필요하다.
3. 비용·API 키·사용 승인·7일 아카이브 제공은 매체별 **미확인**이다. 이번에 요구되는 신규 GitHub Secret은 없다. 계약된 API가 확보된 뒤에만 정확한 Secret 명칭·어댑터를 추가하며 키를 PR/공개 JSON/로그에 넣지 않는다.
4. 승인이 확보되면 기존 PublicationGate에 근거 URL·범위·확인일을 기록하고 소수 발행처부터 단계적으로 활성화한다. 후보 문서의 review를 바꾸는 것만으로 운영 연결되지 않는다.
5. 실제 취재 다양성은 제목만으로 검증 불가하다. 공식 배포 식별자나 권리가 허용된 출처 메타데이터가 제공되기 전에는 독립 취재 수를 확인됐다고 주장하지 않는다.
6. 운영 수집·Pages 배포의 지속 성공은 **사용자 병합 후** main Actions와 `data/live` 커밋, 공개 산출물로 별도 검증해야 한다. 이 PR에서 예약 운영을 성공 처리하거나 main에 병합하지 않는다.
